# GOAL — Hunter Harness 구축

> 이 문서는 하네스 자신의 GOAL이다. 하네스가 관리하는 프로젝트의 GOAL.md와 같은 형식을 따른다.
> 참조: Lilian Weng, "Harness Engineering for Self-Improvement" (2026-07)

## 목표

1인 개발자(백엔드·프론트·AI 에이전트·기획·운영 전담)가 어떤 프로젝트, 어떤 PC에서든
한 줄 설치로 이식해 쓸 수 있는 **목표 지향(goal-driven) 멀티 에이전트 개발 하네스**를 만든다.

## 성공 기준 — 품질 지표 (2026-08-10 개정)

> 개정 사유: 구 SC-1~SC-6 은 전부 **존재 확인**(파일 12개·커맨드 8개·스킬 9종)이었다. 부품이 있는지를 셀 뿐 결과의 질을 세지 않아 "정확도 98%"를 걸 분모가 없었다. 구 기준은 §달성 완료로 이관.
> 기준선은 karechat-cs-agent iteration 14 (`20260807-prompt-resource-consolidation`) 실측이다. 상세 진단: `docs/DIAGNOSIS-2026-08-10.md`.

**M1·M6 이 핵심이다.** 둘 다 사용자 판정 없이 계수되고 둘 다 비용에 직결된다. M3 은 goal 단계 오염을, M5 는 세리머니 과잉을 잡는다.

> M2 는 2026-08-25 에 분할됐다(구 M2 = 에이전트·브리프 합산이라 원인을 지목하지 못함). 구 67% 와 직접 비교하지 않는다.

**계수 조건**: M1·M2·M5·M6 은 **측정 원장**(`.harness/measurements.jsonl`, 스키마·계수식은 `harness-state` 스킬)에서 자동 계수된다 — 2026-08-10 신설. M2·M6 기준선은 karechat-cs-agent 원장 **전체**(archive 포함 d 113건) 실측이다 — 활성 파일만 읽으면 회전 뒤 분모가 잘린다. M3·M4 는 아직 수기다. 원장이 빈 goal 은 「미측정」이지 100% 가 아니다.

## 달성 완료 (구 SC — 구축 단계 기준, 2026-07 ~ 2026-08 충족)

설치 1줄 이식 · 10역할 에이전트 · 8커맨드 전 단계 · `.harness/` 영속화 · 스킬 11종 · 자기 개선 회고 루프. 이들은 **부품의 존재**를 보증할 뿐 위 품질 지표를 보증하지 않는다.

## 제약

- 프롬프트는 영어(모델 성능 최적), 사용자 응답·산출물은 한국어.
- 하네스 개선(회고) 루프는 제한된 편집면만 허용: 플레이북·프롬프트·게이트. 권한/안전 규칙은 편집 금지, 적용은 사람 승인 후.
- 파괴적 작업(운영 배포, 리소스 삭제)은 항상 사람 승인 게이트.
- 1인 유지보수 전제: 지루한 기술(boring tech), 최소 가동부.

## 범위 외

- 모델 가중치 학습/튜닝 (기사에서 말하는 joint optimization은 범위 외)
- 자동 하네스 편집 적용 (제안까지만, 적용은 사람이)
- CI 서버 등 외부 인프라 구축
