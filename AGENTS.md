# AGENTS.md — Codex entry point for the Hunter Harness

This repo is a goal-driven multi-agent development harness for a solo developer, covering the full loop 기획→분석→설계→구현→검증→회고 with 10 role agents, 8 workflow commands, and 11 domain skills.
Source of truth is `plugins/harness/` (Claude Code plugin). Everything under `.agents/` and `.codex/` is generated by `tools/sync-codex.sh` — edit the source, never the generated copies.

## Language rule (non-negotiable)

ALWAYS respond to the user in Korean. Write all artifacts — `.harness/` files, reports, review verdicts — in Korean. Keep code identifiers, file paths, and technical terms as-is.

## `.harness/` state contract (summary)

Full schema lives in the `harness-state` skill (`.agents/skills/harness-state/`). Key rules:

- Files are the only durable truth. If a result is not in `.harness/` (or the codebase), it did not happen.
- Read `.harness/GOAL.md` and `.harness/wiki/INDEX.md` BEFORE starting any task; open only the wiki nodes matching your scope + global/workflow.
- One daily log: append to `.harness/logs/YYYY-MM-DD.md` (append-only, entry format per the skill).
- Insights become wiki nodes: create (candidate) / reinforce / promote per the skill's node lifecycle — no inbox.
- `.harness/plan.md` and `.harness/state.json` are written ONLY by the 코디네이터 (the main session, not a subagent); everyone else treats them as read-only.

## Workflow (skills replace slash commands)

For feature-size work, invoke the wrapper skills in order:

`$cmd-goal` → `$cmd-analyze` → `$cmd-plan` (승인 게이트) → `$cmd-build` → `$cmd-verify` → `$cmd-retro`

Small single-file tasks: `$cmd-quick`. Status check anytime: `$cmd-status`.
Each `cmd-*` skill points at the canonical workflow definition in `plugins/harness/commands/<cmd>.md` — read it and execute it exactly.

Codex does NOT auto-delegate. When a workflow says "delegate to X" or "dispatch the X agent", explicitly spawn the subagent named `X` defined in `.codex/agents/X.toml` (planner, analyst, architect, product-designer, backend-dev, frontend-dev, ai-agent-dev, qa, code-reviewer, harness-improver). Thread limits are set in `.codex/config.toml` (`[agents]`).

## Co-creation rule

At key branch points, ask the user in Korean with 2–4 options plus a recommended default and trade-offs, then record the answer (ADR/PRD) so the same question is never asked twice — protocol in the `co-creation` skill.

## Token budget rule

The wiki is capped (active ≤ 40 nodes, ≤ 8 per scope, node body ≤ 10 lines, INDEX ≤ 80 lines) with INDEX-driven scope-filtered reads; never read the cold storage (`.harness/logs/archive/`, legacy archives under `.harness/retro/`), and never paste file contents into dispatch briefs — agents read files themselves.
