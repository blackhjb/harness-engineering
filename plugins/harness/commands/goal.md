한국어로 응답하고 모든 `.harness/` 파일을 한국어로 쓴다(코드 식별자·경로·기술 용어는 원문). 문서 스캐폴드는 `harness-ledger` 스킬의 정본 섹션 목록에서 직접 생성한다.

## 1. 인터뷰 (한 메시지, 짧게)
한 메시지로 묻는다. **quick 후보면 2문항만**(성공 기준 · 범위 제외); 표준 루프면 최대 4문항(+ 제약 · 기한). 이미 "$ARGUMENTS" 가 답한 것은 묻지 않는다. 성공 기준이 모호하게 오면 측정 가능하게 한 번 재진술하고("이렇게 바꾸면 측정 가능합니다: ... 맞습니까?") 확인 후 진행한다.

**SC 표 확정 체크리스트 — 행마다 전 축(1~8).** 범위 팽창과 vacuous SC 는 실행이 아니라 이 표를 쓰는 순간 태어난다:
1. **측정** — 검증 가능한 값("p95 < 200ms"), 느낌 금지.
2. **수정 전 거짓** — 참이면 vacuous; 인용한 로그 레벨·문자열·상수는 원문 줄을 열어 확인. grep·명령 1회로 1분 안에 확인되면 **지금 돌린다** — "수정 전 red 실측을 태스크에 포함" 유예는 확인이 실제로 비쌀 때만.
3. **경로 식별** — 같은 값이 다른 경로로도 나올 수 있으면 경로 식별 증거를 함께 적는다.
4. **출처** — 행마다 한 단어: `사용자` / `파생`(사용자 SC 달성에 필연) / `제안`(내 판단). `제안` 이 1건이라도 있으면 착수 전에 그 행만 사용자에게 별도 확인한다 — 검증 요청에 리팩터 SC 를 얹는 것이 최대 비용 경로다.
5. **달성 가능성** — §범위 제외와 나란히 읽는다. 제외된 수단 없이는 도달 불가한 SC 는 모순: 목표치를 「판정·사유 등록으로 닫는다」로 낮추거나 그 제외를 푼다.
6. **성과 축** — SC 가 삭제형·구조형이면 목표치는 **프로덕션 순삭제 줄수 또는 분기 델타**로 적는다. 「계측 N개 부착」·「테스트 N개 정리」·「모듈 이동」은 목표치 칸에 쓰지 않는다(성과 아님 — build.md §성과의 정의). 그리고 대상이 「죽은 것 같은 코드」면 **ablation 을 기본 수단으로 적고**, 계측을 쓸 거면 왜 ablation 이 불가능한지 그 행에 1줄 병기한다.
7. **기준선 실존** — SC 가 기준선 수치·측정 도구를 인용하면, 그 수치의 원장 키(`<명령>@<sha7>`) 또는 provenance 산출물 경로를 같은 행에 병기하고 지정 도구는 `git ls-files` 로 지금 실존 확인한다. 산문 로그 1줄만이 출처인 수치는 기준선이 아니라 `[미검증]` 참고값이다 — 재현 불가 기준선은 verify 에서 FAIL 로 되돌아온다.
8. **소비자 결박 — 장치**: SC 의 산출물이 계측·게이트·축·판정표처럼 **측정 수단**이면, 그 행에 `소비: SC-N(<처분 대상 file:line>)` 또는 `소비 유예: <사유> · <소비 goal 착수 조건> · <무산 시 원복 책임>` 을 **값으로 적는다 — 이 값이 비면 스캐폴드하지 않는다**. 소비자가 **읽는 산출물 필드명**을 병기하고 그 필드가 산출물 스키마에 실재하는지 명령 1회로 확인한다 — 산출물에 없는 필드를 읽는 소비자를 지정하면 검증 불가능한 조건이 태어난다. goal 중간의 SC 개정도 이 축을 다시 탄다. 소비가 무산되면 **원복이 기본값**이다 — 이 조항이 문장으로만 있으면 커맨드 본문에 있어도 위반된다(계측만 늘고 삭제 0 인 goal 이 그렇게 태어난다). 그래서 값으로 적게 한다.

## 1-B. 시스템 유형 판별 (유연한 판별 + 선택의 강제 — 생략 금지)
스캐폴드 전에 **이 goal 이 만지는 표면(작업 대상)별로 시스템 성격을 판별해 GOAL.md 승인 섹션에 「표면 → 스킬」 표로 기록**한다. 원칙:
- **판별은 유연하게** — 단위는 goal 이 아니라 **표면**이다. 복합 goal(예: 프롬프트 + Python 라우트 + 배치)은 표면마다 다른 스킬이 맞고, 태스크가 goal 판별과 다른 표면을 만지면 **디스패치 시점에 그 태스크만 재판별해 오버라이드**한다(브리프에 사유 1줄). 예시 매핑(닫힌 목록 아님): LLM 프롬프트·모델 라우팅·eval=`ai-agent-dev` · Python 서비스=`python-service` · Java/Spring=`spring-boot-dev` · 배치/ETL=`data-pipeline` · React=`frontend-dev` · GCP 인프라=`mlops-gcp`. 들어맞는 스킬이 없으면 「특화 스킬 없음 — 범용 진행」을 **명기**한다(그것도 기록된 선택이다).
- **선택은 강제로** — 판별·기록 없이 스킬을 고르는 것(감)과 무지정(중립) 브리프는 금지. 이 표가 design §9 와 analyze·build 브리프 스킬 지정의 정본이다.

## 1-C. 산출 게이트 (생략 금지)

스캐폴드 **전에** GOAL 승인 섹션에 아래를 **값으로** 적는다. 하나라도 못 대면 표적이 확정되지 않은 것이다 — 세우지 말고 먼저 재라.

- **예상 산출**: 이 goal 이 끝나면 `src/` 프로덕션에서 몇 줄·몇 분기가 없어지는가(또는 어떤 사용자 가치가 배포되는가). 측정 축·계측·인벤토리를 **세우는 것은 산출이 아니다** — 그것을 소비해 무엇이 없어지는지까지 적어야 산출이다. **실측 인용만**: 스캔·`git grep` 실행값 또는 원장 키를 병기한다. 추정치는 기재 불가.
- **상위 후보 표**: 도메인·블록별 top-3 를 4열로 — 상금(분기 수) · 검증 비용 · **표적 코드 진입 계수** · **표적 종류(가드/배선/계측)**. 최대가 아닌 표적을 고르면 사유 1줄. 열이 비면 표적 미확정과 같다 **상금 칸에는 실행된 명령의 원장 행만 인용한다 — `key` 가 `derived:` 로 시작하는 파생 행은 기재 불가**(실측 2026-08-26: 파생 상금 0.312s 가 실측 0.007s 로 뒤집혀 goal 전체가 산출 0 으로 닫혔다).
- **목표치의 축**: SC 목표치는 이 goal 이 **직접 바꾸는 구조 값**(분기 수·호출 사이트 수·삭제 행 수)에 결박한다. **지연 초·정답률 pp 같은 결과 지표는 목표치 칸이 아니라 관측 칸에 적는다** — 결과 지표를 목표치로 세우면 그 지표를 움직일 레버의 실재 여부가 착수 후에야 드러나고, 레버가 없으면 goal 은 기각 보고서로 닫힌다. 결과 지표를 목표치로 쓰려면 **그 축을 실제로 움직인 arm 1건의 실측 원장 행**을 같은 줄에 병기한다.
- **예상 디스패치 수**: analyze·design·build 웨이브·verify·retro 합계.

**감축분은 행으로 지목한다**: 목표치가 「X→Y」·「−N」 형태면 그 SC 의 **판정 명령을 기준선에서 1회 실행**하고, 출력에서 없어질 항목을 `file:line` **N행 목록**으로 적는다. 지목 행 수 < N 이면 **목표치는 지목 행 수다**(내림, 사유 1줄). 기준선만 재고 감축분을 유추한 목표치는 기재 불가. 목표치의 축은 판정 명령의 축과 **같은 이름**이어야 한다 — 다르면 그 목표치는 미측정이다.

**진입 계수는 논리곱 전건으로 센다**: 삭제·교체형은 표적 코드가 검증 코퍼스에서 실행되는 횟수를 값으로 적는다. 진입 술어를 소스에서 그대로 옮겨 적고(`<술어 원문 + file:line>`), 절이 N개면 **N개를 모두 만족한 케이스 수** 하나를 낸다 — 절 하나의 발생 수도, 라우트 분포·발동률 유추 상한도 **대리가 아니다**. 절별 계수가 불가하면 진입 마커를 먼저 심는다(생산자 로그 레벨 확인). 마커가 없는 코드는 AST 도달성 + 호출부 grep 을 대체 증거로 허용한다.
**이 값이 0 이면 그 코퍼스로 어떤 SC 도 성립하지 않는다** — 「진입 픽스처 조달」을 SC-0 으로 등재하고 진입 계수 >0 실증을 build 착수 전 인수조건에 넣는다.

**가드는 진입 계수·ablation 으로 삭제 판정할 수 없다**: 삭제 후보가 「거부·롤백·차단·검증」 계열이면 「죽음」과 「방어 대상 사건 미발생」이 **같은 관측(발동 0)**을 낸다. **구/신 구현의 적대적 차등 실행**을 SC-0 으로 등재한다 — 크래프트 입력은 그 가드의 **거부 사유 라벨에서 역산**하고, 믹스인 메서드는 **실제 host 객체를 `self` 로** 넘긴다. 판정이 한 쌍이라도 갈리면 **표적에서 제외**한다.

**게이트**: 삭제형·구조형인데 **예상 산출(분기 델타) < 예상 디스패치 수**면 그 goal 을 세우지 않는다. 표적을 상금표 상위로 바꾸거나 quick 경로로 내린다. 스캔 점수 축을 인용할 때는 식별자 덤프로 **오탐을 먼저 분리**한다.

산출이 「판정·사유 등록」뿐인 goal(무엇도 없어지지 않는 goal)은 **세우지 않는다**. 그 판정이 필요하면 다음 삭제 goal 의 analyze 1건으로 흡수한다.

## 2. 규모 분류 (규모 비례 라우팅 — 생략 금지)
**먼저 `.harness/wiki/INDEX.md` 를 열고 `cost`/`workflow`/`global` 노드를 읽는다** — 아래 임계값은 그 노드가 이기는 기본값이다.
스캐폴드 **전에** 규모를 분류한다. **변경 표면은 grep 실측이 선행 — 문서 추론만으로 라우팅 금지**: 실제로 바뀌는 파일(상수·라우트·컴포넌트)을 찾아 세고, 그 수를 라우팅과 함께 GOAL.md 승인 섹션에 적되 `change-surface`(바뀔 파일)인지 `read-surface`(읽을 파일)인지 **한 단어로 병기**한다. 감사·검증형 goal 은 바뀔 파일을 미리 알 수 없어 read-surface 를 세기 쉽다 — read-surface 는 곧 「규모 미상」이므로 아래 판단-불가 규칙을 탄다. 세리머니는 목표의 중요도가 아니라 실측된 변경 크기에 비례한다.

- **quick 경로** — 전건 충족: **호환성을 깨는 계약 변경 없음** · 아키텍처 결정 0(새 모듈 경계·기술 선택 없음) · 실측 diff 가 국소적·기계적(가드, re-export, 테스트 수정, config/문서 — 대략 ≤8파일 / ≤150줄) · SC 전건이 명령으로 판정 가능.
  - breaking = 필드 제거·rename·타입/의미 변경·필수 요청 필드/인자 추가. **추가형**(새 응답 필드 · 기본값 있는 kwarg · 구 소비자가 무시하는 enum 값)은 quick 을 탈락시키지 않는다 — 어느 쪽인지 구 소비자 동작 근거와 함께 1줄로 명시.
  → §4 대로 스캐폴드하되 analysis/prd/design/plan 은 만들지 않고, 라우팅 + 1줄 근거를 GOAL.md 승인 섹션과 일간 로그에 기록한 뒤 `/harness:analyze` 대신 `/harness:quick`(한 배치, 또는 SC 클러스터당 1회)으로 넘긴다. **검증 엄격도는 경감되지 않는다.**
- **표준 루프** — 그 외 전부, 또는 오판이 비쌀 만한 의심이 있으면 → `/harness:analyze`.
- **판단 불가** — `/harness:analyze` 를 먼저 돌린다. 그 analyze 는 **규모를 재는 패스**이지 증명하는 패스가 아니다(analyze 커맨드의 질문 크기 상한 적용); analysis.md 권고가 경로(quick vs plan)를 명시하고 그대로 진행한다.

임계값(≤8파일/≤150줄)은 retro 가 조정하는 기본값이다 — 프로젝트에 `cost` scope 위키 노드가 있으면 그것이 이긴다. 선택한 경로와 근거를 §5 확인 메시지에 밝힌다.

**문안 확정 게이트**: 산출물이 사용자 눈에 보이는 문자열(문구·라벨·에러·화면 상태)을 포함하면, 착수 전에 **리터럴 3안 이내로 1회 확정**받고 그 문안을 GOAL.md 목표치 칸(또는 design.md §8)에 그 턴에 적는다. 미기재 문안으로는 디스패치하지 않는다 — 문구는 취향이라 착수 후 바뀌면 배선까지 되돌아간다 (로그 참조).

## 2-B. 사실 명제에는 근거를 붙인다 (재작업의 최대 원인)
GOAL 배경·전제의 **사실 명제**(도입 시점·인과 순서·부재 주장·값의 형태·직전 iteration 의 결론)는 각각 `file:line`·커밋 sha·명령 출력 중 하나를 같은 줄에 병기한다. 근거를 댈 수 없으면 `[미검증]` 으로 표시하고 analyze 의 확인 대상으로 넘긴다. 직전 iteration 의 verify 로그·사용자 보고를 그대로 승격하는 것이 가장 흔한 오염 경로다 (로그 참조).

## 3. 기존 .harness/ 처리
- **위키 상한 위반이면 새 goal 전에 `/harness:retro` 먼저** (candidate ≤15, active ≤8 per scope, INDEX ≤80줄) — 큐레이션은 다음 goal 의 선행 조건이다 (로그 참조).
- **장부가 실제와 어긋나면 먼저 맞춘다**: 마지막 verdict 이후 코드가 바뀌었는데 state.json 이 여전히 `done`/PASS 면 그 후속 작업은 미등록 iteration 이다 — `iteration` 증가 + `verify` 리셋으로 등록부터.
- **직전 세션의 백그라운드 잔여를 스캔한다**: ListAgents 로 이 프로젝트의 실행 중 표시 에이전트를 확인하고, 직전 로그의 디스패치 대비 미착지 건은 ①재개 메시지 회수 ②kill+동기 재실행 ③명시 이월 중 하나로 처분 후 진행 — "running" 표시는 생존 증거가 아니다 — 무성 정지는 실행 중으로 표시된 채 몇 시간 간다.
- `.harness/` 없음: 아래 전체 구조 생성.
- `.harness/` 있음: 새 goal iteration. `wiki/`·`retro/`·`logs/` 는 보존(축적 학습). 구 state.json 을 읽어 `iteration` 증가, GOAL/analysis/prd/design/plan 은 새 스캐폴드로 덮는다. 직전 goal 의 phase 가 `done`/`retro` 가 아니면 미완임을 경고하고 명시 확인 후 덮는다.

## 4. 파일 생성 (`harness-ledger` 스킬의 정본 섹션 목록에서)
모든 섹션 존재, 빈 섹션은 "해당 없음".
- `GOAL.md` — 인터뷰 내용으로 채움.
- `analysis.md`·`prd.md`·`design.md`·`plan.md` — **표준 루프만** 생성(헤더만). **quick 경로는 이 4개를 만들지 않는다** — quick 의 장부는 GOAL.md + state.json + 로그다.
- `state.json` — 스킬 스키마대로: `goal_id` = `<yyyymmdd>-<short-slug>`, `base_ref` = `git rev-parse HEAD`(git 아니면 null), `phase` = "goal", `iteration`(1 또는 증가), `updated_at` = now, `approvals` 전부 false, `verify` = {"verdict": null, "date": null}, `tasks` = [].
- `wiki/INDEX.md` — 없을 때만 헤더 + 형식 주석으로 생성; 기존 위키는 절대 덮지 않는다.
- `measurements.jsonl` — 없으면 빈 파일로 생성(`harness-state` §측정 원장). 기존 파일은 절대 덮지 않는다 — append-only 이고 goal 을 가로질러 누적된다.
- `retro/`·`logs/` — 없으면 생성.
- 오늘 일간 로그에 goal-set 항목 append (누가, 무슨 goal, iteration).

## 5. 확인과 핸드오프
사용자에게 한국어로: 성공 기준 표 · 제약 · 범위 제외 · §2 라우팅 결정과 근거를 보여주고 GOAL.md 확정 또는 수정 요청을 받는다. 확정되면 다음 단계는 라우팅된 커맨드다 — quick 경로면 `/harness:quick`, 아니면 `/harness:analyze`. **라우팅이 사용자에게 수동 단계를 추가해서는 안 된다**: 자율 진행 권한("알아서 진행")이 있으면 코디네이터가 같은 세션에서 라우팅된 커맨드를 직접 호출한다.

## Question rules
질문은 `co-creation` 스킬을 따른다; 기록된 결정은 재질의하지 않는다. 예외 — 최초 인터뷰는 기본 사실(기한, 제약 등)을 짧은 개방형으로 물어도 된다.
